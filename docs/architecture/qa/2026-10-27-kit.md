## Findings to act on

1. 🔴 **Must — the size controls stay visible on the kit screen and print with the plan** (FON-02h,
   UI-04b, P0). Not filed (caller asked for no issue).
   - Seen: `<div class="controls" hidden>` is rendered ([Editor.tsx:103](../../../src/web/Editor.tsx#L103))
     but `.controls { display: flex }` ([tokens.css:51-57](../../../src/web/tokens.css#L51-L57))
     overrides the user-agent `[hidden] { display: none }`. The preview figure hides correctly
     because `.preview-figure` sets no `display`.
   - Impact: the buyer can change the width on the kit screen (field shows 3) while the bill, the
     plan and the file name stay 2 × 2; the printed page 1 carries the size inputs and «Tramage»,
     against spec kit.md «a `@media print` style hides the controls».
   - Repro: import a photo, 2 × 2, «Commander mon kit», look above «Votre kit»; print preview.
   - Suggested fix (not applied):
     ```diff
     --- a/src/web/tokens.css
     +++ b/src/web/tokens.css
     @@
     +/* Author display rules must not defeat the hidden attribute. */
     +[hidden] {
     +  display: none !important;
     +}
     +
      body {
     ```
     plus a test asserting the controls are not visible once the kit is shown (jsdom does not
     apply the stylesheet, so the existing `hidden` assertion cannot catch it: a Playwright check
     or a CSS rule test is needed).
2. 🟡 **Should — private advisory S1.** Details to the caller only.
3. 🟡 **Should — focus is lost on both screen changes** (A11Y-01, WCAG 2.4.3).
   - Seen: after «Commander mon kit» `document.activeElement` is the hidden order button; after
     «Retour à l'édition» it is `body`, so the next Tab restarts at the file input. A screen reader
     user hears nothing when the kit appears.
   - Suggested fix: give `h2#kit-title` `tabIndex={-1}` and focus it on mount in
     [Kit.tsx:24](../../../src/web/kit/Kit.tsx#L24); on back, return focus to the «Commander mon
     kit» button ([Editor.tsx:112](../../../src/web/Editor.tsx#L112)).
4. 🔵 Nice — the printed bill does not state the spare rate: `.spares` is hidden in print
   ([tokens.css:204](../../../src/web/tokens.css#L204)), so «À acheter» on paper has no stated
   basis. Print the chosen rate in the caption (e.g. «Liste des pièces (rechange 2 %)»).
5. 🔵 Nice — `* { print-color-adjust: exact }` ([tokens.css:217-219](../../../src/web/tokens.css#L217-L219))
   also prints the beige page surface on every page (visible in 05-print-pages-1-2); scope it to
   `.stud, .swatch, .plate-grid` or set `body { background: none }` in print.
6. 🔵 Nice — 8 × 8 kit: 304 ms from click to frame on the prod build (desktop, unthrottled),
   above the 200 ms INP goal; slower on a phone. Not a defect at this size; measure with a
   throttled trace before #23 adds more per-plate content.
7. 🔵 Nice — `favicon.ico` 404 (UI-08, pre-existing).
8. 🔵 Nice — spare radios are 13 px with 20 px labels: exempt (native control) but below the
   24 px house floor; padding on `.spares label` would help touch users.

Note: spec kit.md says the lowest ink ratio is «5.2:1»; measured 5.16:1 (rounds to 5.2, above
4.5:1). No action.
