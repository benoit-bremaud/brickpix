# QA full — kit: build plan, bill of materials, BrickLink list (2026-10-27)

**Plan.** Product type W only: a static client-side SPA (Vite + React, Cloudflare Workers static
assets, `wrangler.jsonc`), with no API, no account, no cookie and nothing persisted. Diff
`main...HEAD`: kit screen (`src/web/kit/*`, `Editor.tsx`, `tokens.css`) and domain (`kit.ts`,
`brickLinkXml.ts`, `colour.ts`), plus docs. Domains in: FON, UI, A11Y, PERF, SEC, USA, PRI.
Domains out: DAT (no API, no persistence), ROB-01…04/07…12 (no backend, no flags, no firmware),
MOB (no native app). Oracle: `docs/architecture/specs/kit.md`, `diagrams/mosaic/05-state-editor.md`,
issue #9. Regression baseline: `docs/architecture/qa/2026-10-27-kit.md` (pass, head 91faceb).

**Rules of engagement.** Allowed hosts: `localhost`, `prod.localhost`. No account and no seed
needed. No burst (no server route). Nothing irreversible. Product content was read as data: no
instruction found in it.

**Inputs and tools.** Synthetic PNGs only, drawn in the page with a canvas and set on
`input[type=file]` through `DataTransfer` (320 × 240 and 640 × 480 gradients with shapes,
300 × 200 blue/yellow bands, 200 × 200 red, a 6000 × 4000 gradient of 17.7 MB), plus three
broken files (5 random bytes, a text file, an SVG with a script). No personal photo. Tools:
built-in browser pane (journey, spare/XML consistency, copy refused, console, network, storage,
state transitions), Playwright MCP Chromium (saved screenshots, clipboard granted, download, print
media and A4 PDF, viewports, forced colors, text zoom, axe-core 4.14, CPU throttling and Event
Timing, heap), standalone Playwright 1.5x (Firefox r1555, WebKit r2370) for the cross-engine
run, `curl` for the dev-server probes. `qa-doctor`: all required tools present; Orca missing
(`sudo apt install orca`), hence A11Y-14 not tested.

## Findings to act on

1. 🔴 **Must — «Commander mon kit» blocks the page well above the INP budget** (PERF-01, P0;
   USA-05) → #28.
   - Seen: Event Timing `click` duration on the production build, photo 640 × 480 dithered:
     8 × 8 344–376 ms unthrottled and 1080–1344 ms at 4× CPU (one 1316 ms long task); the
     default 3 × 3 is 224 ms at 4× CPU. Split: `computeMosaic` 84 ms, `buildPlan` 1 ms, bill and
     XML < 1 ms; the rest is the React commit, style and layout of 17 488 DOM nodes. Nothing
     tells the user the page is working.
   - Expected: INP ≤ 200 ms on the mobile profile, or feedback within 100 ms and progress
     beyond 1 s.
   - Repro: prod build, 4× CPU, import a photo, 8 × 8, «Tramage», «Commander mon kit».
   - Lead (measured by injecting the rule, not applied): `.plate { content-visibility: auto;
     contain-intrinsic-size: auto 40rem; }` halves the cost (8 × 8: 344 → 152 ms at 1×,
     1080 → 616 ms at 4×). Not enough alone at 8 × 8 on 4×: a busy state or a progressive
     render of the plates changes the «synchronous recompute» decision of `specs/kit.md`, so
     the spec comes first. The owner may instead record a waiver for the maximum size; quote it
     here if so.
2. 🟡 **Should — private advisory S1.** Details to the caller only.
3. 🟡 **Should — stud and swatch colours are lost in forced-colors mode** (UI-04, P1) → #29.
   Numbers and names remain, so the plan stays usable, but the colour picture is gone.
